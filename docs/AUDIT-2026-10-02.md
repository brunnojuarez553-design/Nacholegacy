# Auditoría de Nacho’s Legacy — 2 de octubre de 2026

Alcance: repositorio completo en `c14d464`, página pública, navegación, textos, formulario de evaluación, galería, asistente, indexabilidad y configuración de Vercel. No se tuvo acceso a Search Console, Google Business Profile, Analytics ni métricas de usuarios. No se presentan puntajes de Lighthouse ni resultados de posicionamiento como si hubieran sido medidos.

## Hallazgos y resolución

| Prioridad | Evidencia inicial | Cambio |
| --- | --- | --- |
| Crítica | Seis servicios con `href="#"`; el contenido ampliado vivía únicamente en modales | Seis páginas HTML de servicios con URL, contenido, título, descripción, enlaces relacionados y schema Service propios |
| Alta | Un único documento con CSS y JavaScript incrustados | Plantillas, secciones, datos de negocio y assets separados; generación estática sin dependencias externas |
| Alta | Español activado por JavaScript y localStorage, sin URL propia | 13 páginas en inglés y 13 en español, disponibles en HTML desde la respuesta inicial, con enlaces de idioma y hreflang recíprocos |
| Alta | Sin canonical, sitemap, robots ni datos estructurados | Canonical por página, sitemap de 26 URLs, robots, AutoBodyShop, WebSite, WebPage y BreadcrumbList; Service en páginas correspondientes |
| Alta | Formulario impedía el envío y mostraba “Visual demo completed”; fotografías sin backend de subida | Formulario prepara los datos en SMS/iMessage; visitante revisa y envía. Se elimina el selector de subida y se explica que las fotos deben adjuntarse en la app de mensajes |
| Media | Bloques de “PHOTO PLACEHOLDER” y futura integración de reseñas visibles | Retirados de la experiencia pública. No se inventaron testimonios ni AggregateRating |
| Media | Contenido `.reveal` inicialmente invisible sin JavaScript | Texto visible por defecto, compatible con lectura y navegación sin JS |
| Media | Reproducción de video reintentada continuamente, botón de pausa oculto, precarga pesada | Precarga de metadatos, poster, control de pausa visible y consideración de movimiento reducido |
| Media | Modales sin confinamiento de foco; tamaños de campos podían activar zoom móvil | Roles de diálogo, navegación de foco, Escape, enlace para saltar al contenido y campos de 16 px |
| Media | Título y descripción sustituidos globalmente por el selector de idioma | Metadatos persistentes y únicos generados para cada página |
| Media | Sin página de error ni estructura de navegación rastreable entre secciones | Página 404, navegación principal y pie, enlaces reales de servicios y breadcrumbs |
| Baja | Sin previews de redes definidos | Open Graph, Twitter Card y favicon con assets actuales |

## Arquitectura implementada

- `/`: portada y resumen de servicios, información local y contacto.
- `/services/`: catálogo de servicios.
- `/services/collision-repair/`
- `/services/frame-repair/`
- `/services/auto-refinishing/`
- `/services/insurance-claim-support/`
- `/services/dent-body-repair/`
- `/services/paint-color-matching/`
- `/about/`, `/repair-process/`, `/our-work/`, `/faq/`, `/contact/`.
- Versiones equivalentes bajo `/es/`.

Se conservaron imágenes, identidad visual, teléfono, correo, ubicación y horario presentes en el repositorio. El inglés sigue siendo la versión principal para el mercado local de Pennsylvania. No se crean páginas masivas de ciudades sin contenido propio.

## SEO y GEO

El cambio se centra en contenido accesible, páginas por intención de búsqueda, enlaces internos y datos consistentes del negocio. Las páginas describen el alcance de cada servicio, lo que debe aportar el cliente y la necesidad de inspección. La información debe poder entenderse sin ejecutar el asistente ni abrir modales.

`llms.txt` funciona como referencia adicional. No es un requisito de Google, no sustituye el sitemap y no garantiza menciones en respuestas de IA. Tampoco se promete posición, plazo de indexación o aumento de tráfico.

## Pendientes externos y mejoras posteriores

1. Verificar el dominio final que utilizará el negocio. `src/data/site.json` usa el dominio de Vercel actualmente informado; `SITE_URL` permite generar canonicals y sitemap para un dominio personalizado.
2. Confirmar con el dueño horarios, nombres, experiencia y datos comerciales heredados antes de ampliarlos.
3. En Search Console, enviar `/sitemap.xml` e inspeccionar las principales páginas una vez publicada la versión. No se accedió a esta cuenta.
4. Confirmar el estado del Perfil de Google y su correspondencia con dirección, teléfono y dominio. Conectar reseñas reales cuando se disponga del perfil adecuado.
5. Publicar casos propios con autorización: daño inicial, trabajo realizado, fotos y explicación de resultados. La galería conserva fotos existentes; no se inventa el contexto de cada reparación.
6. La evaluación por SMS es una derivación, no una solicitud guardada en CRM. Si se necesita recepción automática y archivos, implementar un endpoint, almacenamiento y política de privacidad acorde al flujo real.
7. El asistente usa `GROQ_API_KEY` de Vercel. Las pruebas locales simulan el proveedor; la disponibilidad en producción depende de esa configuración. Añadir límites de consumo y protección contra abuso en una siguiente etapa.
8. Medir Core Web Vitals y conversiones reales tras publicación. Videos, mapas e imágenes de terceros pueden afectar tiempos de carga; no se midieron LCP/INP/CLS de usuarios reales en esta auditoría.

## Verificación reproducible

`npm run build` genera 26 páginas. `npm test` verifica títulos y descripciones únicos, un H1 por página, canonicals, idioma, hreflang, JSON-LD, enlaces locales, sitemap y controles compartidos. También comprueba método HTTP, mensaje vacío, filtrado de acciones y fallo del proveedor en el asistente con respuestas simuladas.

La vista previa local sirve HTML y assets; `/api/chat` se ejecuta en Vercel y no se simula como un envío recibido en el taller.
